# 运行操作手册（macOS）

> 本文说明 DeepSeek HARNESS Quant 在 macOS 上的日常运行方式：哪些服务要开、怎么启停、
> 每天要跑什么、定时任务怎么配。命令均以项目根目录为工作目录。

---

## 一、系统组件与是否常驻

| 组件 | 入口 | 是否常驻 | 说明 |
|---|---|---|---|
| **看板服务** | `deck/deck_server.py`（:8787） | 按需启动，不常驻 | 浏览器页面 / 回测 / 决策审批的入口，纯读数据 + 触发计算 |
| **数据管道** | `data/daily_pipeline.py` | 每天收盘后跑一次 | 增量入库 → 机会扫描 → Pitch → 因子池 → 择时，跑完即退出 |
| **定时任务** | launchd（18:30 / 20:00） | 常驻（launchd 托管） | 自动触发数据管道（18:30）与自动选股+日报（20:00） |

结论：**看板服务想看的时候才开，看完就关；数据管道每天收盘后跑一次；定时任务装一次即可。**

三者互相独立：数据管道直接读写 `data/cache/` 下的库与 `logs/` 下的产物，跟看板服务开没开无关。

---

## 二、每日操作流程（典型一天）

1. **收盘后（~18:30 自动）**：launchd 定时任务自动跑 `data/daily_pipeline.py`。
   - 如果没装定时任务，就双击「运行数据管道.command」手动跑一次。
2. **晚间（20:00 自动，仅工作日）**：`data/daily_report_auto.py` 自动选股 + 生成日报 `report/daily_report_*.md`。
   - 看板「日报」页读的就是这个文件；没等到 20:00 时可手动跑（见四.4）。
3. **想查看结果时**：双击「启动看板.command」，浏览器打开 http://127.0.0.1:8787。
4. **看完关掉**：在看板终端窗口按 `Ctrl+C`，或直接关闭窗口。

---

## 三、双击启动文件（推荐，无需敲命令）

项目根目录下有 3 个 `.command` 文件，双击即在终端中运行（首次双击 macOS 可能弹「是否打开」，点「打开」即可）：

| 文件 | 作用 | 运行后 |
|---|---|---|
| `启动看板.command` | 启动看板服务 :8787 | 前台运行，`Ctrl+C` 或关窗口即停 |
| `运行数据管道.command` | 手动跑一次每日数据管道 | 实时显示全链日志，跑完自动结束 |
| `安装定时任务.command` | 安装 18:30 管道 + 20:00 日报定时任务（装一次） | 复制 `deploy/macos/` 下全部 plist 到 `~/Library/LaunchAgents/` 并 `launchctl load` |

> `.command` 文件内部会先 `cd "$(dirname "$0")"` 定位到项目根目录，因此**从 Finder 双击、无论当前在哪，路径都正确**。

## 四、命令行操作（等价方式）

以下命令均在项目根目录执行，`<REPO>` 代表项目绝对路径（例如 `/Users/yourname/Projects/deepseek-harness-quant`）。

### 1. 启动看板

```bash
cd <REPO>
.venv/bin/python deck/deck_server.py --port 8787
# 浏览器打开 http://127.0.0.1:8787
```

关闭：前台终端按 `Ctrl+C`。

后台常驻版（不占终端）：

```bash
nohup .venv/bin/python deck/deck_server.py --port 8787 > logs/deck.log 2>&1 &
# 关闭
pkill -f "deck/deck_server.py"
```

### 2. 运行数据管道

```bash
cd <REPO>
.venv/bin/python -X utf8 data/daily_pipeline.py
```

### 3. 定时任务（launchd）

```bash
# 安装（-w = 开机自启）
launchctl load -w ~/Library/LaunchAgents/com.dshquant.daily-pipeline.plist

# 验证已加载
launchctl list | grep dshquant

# 手动触发一次（不等 18:30）
launchctl start com.dshquant.daily-pipeline

# 看日志
tail -f logs/launchd-daily-pipeline.out.log

# 卸载
launchctl unload ~/Library/LaunchAgents/com.dshquant.daily-pipeline.plist

# 日报任务（20:00）同样方式安装/手动触发
launchctl load -w ~/Library/LaunchAgents/com.dshquant.daily-report.plist
launchctl start com.dshquant.daily-report
tail -f logs/launchd-daily-report.out.log
```

### 4. 生成日报（手动）

```bash
cd <REPO>
.venv/bin/python -X utf8 data/daily_report_auto.py --dry-run   # 只出日报不写池（验证）
.venv/bin/python -X utf8 data/daily_report_auto.py             # 正式：自动选股入 D 池 + 日报
```

## 五、定时任务（launchd）说明

- **配置文件**：`deploy/macos/com.dshquant.daily-pipeline.plist`（`plutil -lint` 已通过校验）。
- **Label**：`com.dshquant.daily-pipeline`
- **触发时间**：每天 18:30（`StartCalendarInterval`：Hour=18, Minute=30）。
- **工作目录**：项目根目录（`WorkingDirectory`）。
- **环境变量**：`LWQUANT_CACHE_DIR` 指向 `data/cache`（`bars.db` 所在处）；`PATH` 带 `.venv/bin`。
- **RunAtLoad = false**：加载时不立即执行，只在 18:30 触发。
- **日志**：`logs/launchd-daily-pipeline.out.log`（标准输出）+ `.err.log`（错误）。

`安装定时任务.command` 会先 `launchctl unload` 再 `load -w`，避免重复加载报错。

### 日报任务（20:00）

- **配置文件**：`deploy/macos/com.dshquant.daily-report.plist`。
- **Label**：`com.dshquant.daily-report`
- **触发时间**：工作日（周一~周五）20:00（`StartCalendarInterval`：Hour=20, Minute=0, Weekday=1-5，与「周末跳过」约定对齐）。
- **职责**：`data/daily_report_auto.py`（自动选股入 D 池 `ai_select` + 生成 `report/daily_report_*.md`）。
- **日志**：`logs/launchd-daily-report.out.log`（标准输出）+ `.err.log`（错误）。

## 六、注意事项与数据边界

1. **周末自动跳过**：`daily_pipeline.py` 内置非交易日判断（周六日跳过，周一自动恢复），18:30 触发也不会白跑，无需额外配日历。

2. **防并发**：脚本内有锁文件 `data/logs/daily_pipeline.lock`，上一轮没跑完、下一轮又触发时自动跳过，避免并发写冲突。

3. **Tushare token 未配置时**：
   - `incremental_daily_tushare.py`（日线增量）需要有效 Tushare token（`config/params.yaml` 的 `data.tushare_token`）。
   - 未配置时该步骤会失败，但**不阻塞整链**（脚本已做成失败即跳过，日志会提示），其余步骤照常。

4. **macOS 上的数据边界**：
   - 分钟 7z 那步引用 Windows 的分钟数据目录，macOS 上大概率拿不到，会跳过。
   - 真正能在 macOS 跑通的是：沪深300指数刷新、择时红绿灯、机会扫描 / Pitch（前提是 `bars.db` 有数据）。

5. **换手率数据边界**：`turn` 字段 2019 年前缺失，换手类结论一律以 2019+ 为验证区间（见 `AGENTS.md`）。

## 七、常见问题

| 现象 | 处置 |
|---|---|
| 双击 `.command` 提示无法打开 | 右键 → 打开；或 `chmod +x 文件名.command` |
| 看板「日报」页 404 | 日报还没生成：手动跑 `data/daily_report_auto.py --dry-run` 出报告；20:00 任务跑通后自动恢复 |
| 定时任务没触发 | `launchctl list \| grep dshquant` 看是否加载；再看 `logs/launchd-daily-pipeline.*.log` |
| 看板打不开 8787 | 确认 `启动看板.command` 是否在运行；`pkill -f deck_server` 后重启 |
| 数据管道某步失败 | 属正常跳过（见第六节 3/4），看 `logs/` 里对应步骤日志 |
