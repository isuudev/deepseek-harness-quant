# 今日信号开源重实现（report/daily_signal.py）

> 2026-09-10 · 替代原外包包「今日信号」模块。原模块未随源码分发（决策链该环节长期缺文件，
> 页面显示「今日信号 未生成（外包未接入）」）。本实现为**反推消费契约后的开源重写**，
> 不还原外包代码（其无源码），只对齐契约与铁律。

## 1. 铁律与设计原则

- **铁律② 同源**：买入指令 = L2 决策卡聚合，无第二套推荐逻辑。
- **铁律⑦ L0 门控**：数据审计闸门（risk/data_audit）FAIL → 阻断，不生成买入清单。
- **铁律⑨ 写保护免疫**：时间戳主写 `output/daily_signal_<YYYYMMDD_HHMMSS>.json` + 固定名兜底 `output/daily_signal.json`；消费方一律 glob 取最新。
- **动态化铁律**：阈值全在 `config/params.yaml` 的 `daily_signal` 段（模板同步 `.example`），代码只读取。
- **宁缺毋滥**：减仓/离场档只减不加；无候选即空清单，不随机补抽（分层抽样仅为模拟盘跟踪兜底，明确标注非买入指令源）。

## 2. 生成链

```
1) 数据审计闸门 DataAuditor.gate()（quick）── FAIL → gate{ok:false}，清单全空
2) v3 组合 strategy/equal_weight_timing.portfolio(date)
     → regime_cash_ratio（动态择时优先 + RegimeDetector 兜底）/ codes（硬过滤池）/ n_passed
3) Regime 档位：cash ≥ exit_cash(1.0) → exit（清仓语义）
               cash ≥ half_cash(0.5) → half（只减不加，不生成清单）
               其余 → full
4) 买入指令（仅 full 档 + 闸门放行）：
     a. L2 决策卡同源聚合：_pitch_candidates() 中「待审批」卡按 score 降序取 max_buy_n(5) 只
        （pitch_v2 长线 + tech_pitch 短线，长线优先去重，状态 = deck_decisions 最近 action）
     b. 降级①：机器决策池 output/pool_layers_*.json 的 decision 层（src=machine_pool）
     c. 降级②：v3 硬过滤池内按行业分层抽样（日期种子可复现，src=v3_universe）
5) hold_plan = 机器决策池 decision 层前 max_hold_n(20) 只（live_api 机会池「系统建议」补位用）
6) regime_label：RegimeDetector 五档映射（panic→strong_downtrend、uptrend_volatile→uptrend；
   过渡期代理，宏观库接入后替换）
7) 落盘 + 控制台摘要
```

性能：v3 全市场硬过滤约 5 分钟 → 按 date 缓存 `output/v3_portfolio_cache_<date>.json`，
同日晚间链（17:30 / 22:00 / dev_auto 4h）后续轮秒级复用；日期变化自动失效。

## 3. 消费契约（字段 → 消费方）

| 字段 | 消费方 |
|---|---|
| date / generated_at | live_api 链节点内容日期、paper_tracker |
| regime_label | live_api 总览、timing_system 宏观分、ui_v2 holdings |
| regime_level / regime_cash_ratio | live_api 总览、dev_auto→pool_layers 防守档、ui_v2 holdings、paper_tracker |
| n_passed | live_api 漏斗「硬过滤通过」、paper_tracker |
| codes | position_monitor（v3 持仓清单）、paper_tracker（等权净值） |
| buy_order / n_hold | 压测 B 组、今日指令面板 |
| hold_plan | live_api 机会池「系统建议」标记 + 补位（#180） |
| gate{ok,reason} | live_api 总览、live_patch.js 闸门横幅 |
| advice | live_patch.js「今日指令」advice-box |
| capital | dev_auto 读固定名文件 → pool_layers --capital |
| pitch_degraded / sample_method | 压测 B 组、降级溯源 |

## 4. 接口（validation 契约）

- `_pitch_candidates() -> list[{code,name,otype,score,src,status}]`
  （src ∈ pitch_long/tech_short；status ∈ 待审批/已买入/已放弃；坏 JSON 源跳过；
   name←code、otype/score 显式 None；code 大小写归一；长线优先去重）
- `_latest_decisions() -> list`（deck_decisions 最近文件，JSON 数组）
- `v3_portfolio(date) -> dict`（equal_weight_timing 同源 + 按日缓存；压测可 monkey-patch）
- `generate(date=None, capital=None, skip_audit=False) -> dict`（含落盘，返回完整结果）
- CLI：`python report/daily_signal.py [--date D] [--capital N] [--no-audit]`，无参默认最新交易日
- 模块级 `BASE` / `OUT_DIR` 在**调用时**解析（压测运行时会改指临时目录）

## 5. 配置（config/params.yaml → daily_signal 段）

| 键 | 缺省 | 说明 |
|---|---|---|
| capital | 200000 | 资金规模参照 |
| max_buy_n | 5 | 买入清单上限（对齐 risk.max_positions ≤5） |
| max_hold_n | 20 | hold_plan 上限（策略决策池 20 只） |
| half_cash / exit_cash | 0.5 / 1.0 | 减仓档 / 离场档现金阈值 |
| portfolio_cache | true | v3 组合按日缓存开关 |

## 7. 已知边界（如实披露）

1. **审计闸门语义**：若 data_audit 存在 FAIL 项（历史 C5 ST 标记等），信号会显示
   「闸门阻断，不生成买入清单」——这是铁律⑦的**正确行为**，不是 bug；修数据或调整
   `data_audit.strict` 后自动恢复。
2. **首跑耗时**：dev_auto 首轮 daily_signal 子进程超时已放宽至 1200s（首跑硬过滤约 5 分钟）；
   缓存生效后秒级。
3. **A1c 数据依赖**：压测 A1c 断言「当前全部待审批」取决于 deck 实况，若用户在压测前审批过
   卡片，该项失败属数据变化而非实现错误（其余 A 组项不依赖数据）。
4. **降级链真实性**：分层抽样/机器池降级条目 `src` 标记（machine_pool / v3_universe）与
   pitch 同源条目（pitch_long / tech_short）区分，消费方可识别指令来源，不混淆推荐逻辑。
5. **regime_label 与 regime_cash_ratio 口径不同源**：label 为 RegimeDetector 日频状态
   （过渡期代理），cash 为动态择时月度档——原设计如此，label 仅作展示/宏观分参考。
