# 外包市场数据投递契约：温度 / 宽度 / 拥挤度三件套

> 适用：外包因子池（量化代码库思路库/因子池）向主系统投递市场级数据。
> 背景：Deck 状态栏「环境」四项（温度/宽度/拥挤度/择时）中前三项依赖本契约的三类 JSON；缺失时前端显示「—」（设计内兜底，不崩溃），情绪/宽度/风格分自动回退 bars 兜底。

## 0. 消费链路（谁在读）

| 消费者 | 路径 | 用途 |
|---|---|---|
| `deck/live_api.py` `/api/live/timing_dash` | `data/factorpool/output/*` | 状态栏 temp_hist / width_hist / crowd_hist + 温度五指标 + 拥挤摘要 |
| `deck/live_ticker.js` | 消费上述 API（60s 轮询） | 「环境」状态栏渲染，取序列末值 |
| `factors/policy/timing_system.py` | 同上 | 情绪分（sentiment_score）/ 宽度分（breadth_score）/ 风格门控（_style_state） |

## 1. 投递目录

```
data/factorpool/output/
```

- 即主系统内「外包因子池」的 output 目录（`scripts/build_update.py` 路径映射：`量化代码库思路库/因子池` → `data/factorpool`）。
- 消费端一律用相对路径 glob + `os.path.getmtime` 排序取最新；**服务进程 CWD 必须是项目根**。
- 同日多版本允许（文件名带日期/时间戳唯一即可），消费者取 mtime 最新。

## 2. 三件套 schema（glob 模式 → 消费字段）

### 2.1 情绪温度计 —— `market_emotion_temp*.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `temp` | number | 0-100，**越低越恐慌=买入区**（H5/H23/H30 五指标加权） |
| `zone` | string | 恐慌底部 / 偏冷 / 中性 / 偏热 / 过热 |
| `components` | object | 五指标构成（宽度/行业轮动/涨停情绪/动量/分化修正），迷你条展示 |
| `date` | string | `YYYY-MM-DD`（建议） |

- 消费端：`live_api` 取每文件 `temp`（round 1 位）建 temp_hist → 状态栏温度；最新文件 `components`/`zone` → 迷你条/分区标签。
- `timing_system.sentiment_score`：zone 映射 恐慌底部90/偏冷70/中性50/偏热30/过热15；缺失 → bars 涨停密度兜底。

### 2.2 市场快照扩展 —— `market_snapshot_ext_*.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | string | `YYYY-MM-DD`（**必须**：#135 新鲜度检查，滞后 >3 交易日判过期、风格判定跳过） |
| `width5` | number | 0-1 个股宽度（5 日动量占比；H5b 反向：<0.35 恐慌加仓区）→ **状态栏宽度** |
| `ind_breadth_60` | number | 0-1 行业轮动强度（H30：<0.2 恐慌底部 / >0.8 高位钝化） |
| `divergence_60` | number | 大小盘分化（H27：>0 大盘强 / <0 小盘强） |
| `crowding_pctile` | number | 0-1 C-10 量化拥挤度（>0.8 过热预警，风格门控叠加） |

- 消费端：`live_api` 取每文件 `width5`（round 3 位）建 width_hist → 状态栏宽度。
- `timing_system.breadth_score`：0.4×width5 分 + 0.6×ind_breadth_60 分；缺失 → bars 上涨家数兜底。

### 2.3 拥挤度 —— `crowding_*.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `crowding_pctile_252` | number | 252 日拥挤分位（**冷清=机会区**）→ **状态栏拥挤度** |
| `crowding_mkt` | number | 市场拥挤度（摘要卡） |
| `zone` | string | 分区标签 |
| `n_crowded_stocks` | number | 拥挤个股数 |
| `date` | string | `YYYY-MM-DD` |

- 消费端：`live_api` 取每文件 `crowding_pctile_252`（round 4 位）建 crowd_hist → 状态栏拥挤度；最新文件 → 拥挤摘要卡。

## 3. 投递方式（三选一）

### A. 本地重构生成器（★当前推荐，外包池未随源码分发）

外包因子池三方代码未提交时，用本地重构生成器从 bars.db 实算三件套：

```bash
python data/factorpool/market_products.py            # 最新完整交易日
python data/factorpool/market_products.py --backfill 60   # 回溯 60 日补历史
```

口径见该脚本 docstring（width5/ind_breadth_60/divergence_60/涨停密度/拥挤分位，阈值沿自主系统实证注释；权重为重构默认值）。每日自动：`data/daily_pipeline.py` 步骤 2.8 已挂接。

### B. 完整因子池代码库同步（可自产，还原外包原口径）

把外包因子池整体同步进 `data/factorpool/`：

```bash
python scripts/import_factorpool.py --from <因子池目录>   # 幂等，可重复
```

之后由池内 `core/scheduler.py daily` 生成三件套。主链路已挂接：
`data/daily_pipeline.py` 步骤 2.7（收盘后补跑，timeout 2700s）+ 17:30/17:35 计划任务。

### C. 直接投递 JSON

外包伙伴每交易日盘后把三件套落盘到 `data/factorpool/output/`（无需重启服务：timing_dash 60s 轮询 + 版本缓存自动失效）。允许盘中高频投递，文件名需唯一。

## 4. 验收

```bash
python data/verify_outsourced_market.py          # 人读报告 + 模拟状态栏显示
python data/verify_outsourced_market.py --json   # 机器可读
```

- 退出码 0 = 三件套齐备 → 状态栏温度/宽度/拥挤度亮起；1 = 有缺口（诚实反映"数据未接入"，非系统故障）。
- 验收口径与消费端逐字对齐（glob 模式/字段名/round 精度），PASS 即可信。

## 5. 红线（不可违反）

1. **禁止编造数据**：拿不到就缺失，前端显示「—」/ bars 兜底；绝不投递伪造数值。
2. 行情数据来自第三方，仅限本机研究使用，禁止再分发。
3. 投递文件必须与本契约 schema 一致；字段缺失会被消费端静默跳过（文件不报错），验收脚本会逐项列出。
